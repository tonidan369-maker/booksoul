# الاستضافة المحلية للوحة BookSoul والتحكم المركزي

## التشغيل السريع

انسخ `.env.example` إلى `.env` ثم حدّث القيم. بعد تثبيت Docker وDocker Compose:

```bash
cp .env.example .env
docker compose -f docker-compose.local.yml up --build
```

تظهر لوحة الإدارة على `http://localhost:8088` وتعمل خدمة التحكم داخليًا على المنفذ `8080`. لا تنشر منفذ خدمة التحكم؛ يستدعيها Dashboard من خلال `CONTROL_PLANE_URL` عند تشغيل النشر الآمن.

## إدارة الأسرار

لا تضع `CONTROL_PLANE_TOKEN` أو مفاتيح مزودي النماذج أو مفاتيح MCP داخل Flutter Web أو في Git. تحفظ هذه القيم في `.env` للاستضافة المحلية أو في متغيرات Dokploy السرية. مفتاح Supabase Publishable/Anon فقط هو قيمة بناء عامة.

## الوكيل ومزودو النماذج وMCP

خدمة `control-plane` توفر مسارات محمية لحالة التكاملات، واختبار أهداف API المسموح بها، ومحادثة وكيل في وضع **خطة غير منفذة**. هذا مقصود لمنع الأوامر النصية من تنفيذ تغييرات حساسة دون مصادقة وسياسة أدوات صريحة. يمكن لاحقًا ربط مزود نماذج في الخادم وإضافة منفذ MCP في `MCP_SERVER_URL`، ثم تفعيل منفذ تنفيذ أدوات مُراجع بحسب الصلاحيات.

| العنصر | الوضع في هذا الإصدار | خطوة التوسعة الآمنة |
|---|---|---|
| API testing | صحة الخدمة وSupabase وMCP ضمن قائمة سماح | أضف targets محددة، لا تسمح بعناوين URL حرة لتجنب SSRF |
| MCP server | قراءة الحالة من متغير بيئة | إضافة عميل MCP server-side مع OAuth أو key server-side فقط |
| مزود نموذج | مؤشر إعداد للجهة المزودة | ربط SDK على control-plane مع مفتاح محفوظ كـ secret |
| وكيل التحكم | محادثة في وضع خطة | إضافة tool executor مُصادق وصلاحيات لكل أداة وتدقيق أحداث |
| تحكم التطبيق | Supabase وواجهات إدارية | ابدأ بعمليات محكومة مثل نشر كتاب وإرسال إشعار، ثم وسّع تدريجيًا |

## التحقق

بعد التشغيل تحقق من:

```bash
curl http://localhost:8088/healthz
curl http://localhost:8080/healthz
```

> لا تشغّل هذه الحزمة على الإنترنت العام مع منفذ `8080` مكشوفًا. في Dokploy استخدم `expose` فقط لخدمة التحكم، واجعل نطاق Dokploy يمر إلى Dashboard على المنفذ الداخلي `80`.
